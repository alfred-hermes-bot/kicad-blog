KiCad ist von Haus aus ein mächtiges Werkzeug – aber eines der bestgehüteten Geheimnisse ist der Plugin and Content Manager (PCM). Damit erweiterst du KiCad um zusätzliche Werkzeuge, Bibliotheken, 3D-Modelle und Farbthemen – ganz ohne manuelles Kopieren von Dateien. In diesem Beitrag zeigen wir dir, wie du Plugins installierst, woher du sie bekommst und wie du sie wieder loswirst.

Was du lernst

  • Was der Plugin and Content Manager (PCM) ist und welche Paketarten es gibt
  • Plugins aus dem offiziellen KiCad-Repository suchen und installieren
  • Plugins direkt von einer URL installieren
  • Installierte Pakete aktualisieren und deinstallieren

Voraussetzungen

  • KiCad 10 installiert (siehe unseren Installationsguide)
  • Eine Internetverbindung
  • Grundlegende Kenntnisse der KiCad-Benutzeroberfläche

Was ist der Plugin and Content Manager?

Der PCM ist KiCads zentrale Anlaufstelle für Erweiterungen. Er verwaltet vier Arten von Paketen:

Paketart Beispiele
Plugins Zusatzwerkzeuge im Schaltplan- und PCB-Editor, z. B. BOM-Exporte, DFM-Prüfungen, Bemaßungs-Helfer
Bibliotheken Symbol- und Footprint-Bibliotheken von Herstellern wie SparkFun oder Adafruit
3D-Modelle STEP-/WRL-Modelle für die 3D-Ansicht
Farbthemen Alternative Farbschemata für die Editoren

Die Pakete stammen standardmäßig aus dem offiziellen KiCad-Repository (https://plugins.kicad.org). Dort prüft das KiCad-Team die Einträge, bevor sie erscheinen.

Schritt 1: Den PCM öffnen

  1. Starte KiCad – der Projektmanager genügt, du brauchst kein offenes Projekt
  2. Gehe zu Tools → Plugin and Content Manager

Der PCM ist in drei Reiter unterteilt:

  • Browse – alle verfügbaren Pakete aus dem Repository
  • Installed – deine installierten Pakete
  • Updates – Pakete, für die eine neue Version verfügbar ist

Über das Zahnrad-Symbol oben rechts erreichst du die Einstellungen, dort kannst du später auch eigene Repository-URLs hinterlegen.

Schritt 2: Plugin aus dem Repository installieren

  1. Wechsle zum Reiter Browse
  2. Nutze das Suchfeld oder filtere über die Kategorien links (z. B. Plugins)
  3. Klicke auf ein Paket, um Details zu sehen: Beschreibung, Version, Homepage und die kompatible KiCad-Version
  4. Klicke auf Install
NoteWo landet der Inhalt?

Der PCM speichert Pakete im KiCad-Benutzerordner, auf Windows typischerweise unter
C:\Users\<Name>\AppData\Roaming\kicad\10.0\3rdparty\
Plugins liegen dort im Unterordner plugins. Enthaltene Bibliotheken werden automatisch in den globalen Bibliothekstabellen registriert – du musst nichts weiter konfigurieren.

Wichtig bei Plugins: Action-Plugins werden beim Start von KiCad geladen. Nach der Installation starte KiCad einmal neu – danach erscheint das Plugin je nach Art als eigener Menüeintrag oder Toolbar-Button im Schaltplan- oder PCB-Editor.

Plugin testen

  1. Starte KiCad neu
  2. Öffne einen Schaltplan- oder PCB-Editor
  3. Suche im Menü (oder in der Toolbar) nach dem neuen Eintrag

Taucht der Eintrag auf, war die Installation erfolgreich.

Schritt 3: Plugin von einer URL installieren

Nicht jedes Plugin liegt im offiziellen Repository – manche Entwickler veröffentlichen ihre Pakete direkt auf GitHub oder auf einem eigenen Server. Dafür gibt es zwei Wege.

Methode A: Direkt von einer Paket-URL

  1. Klicke im PCM auf den Pfeil neben Install from File und wähle Install from URL

  2. Füge die direkte URL zu einer Paket-.zip-Datei ein, z. B. den Download-Link eines GitHub-Releases:

    https://github.com/<Nutzer>/<Projekt>/releases/download/v1.2/plugin-1.2.zip

  3. Klicke auf Install – der PCM lädt das Archiv herunter, prüft die Kompatibilität und installiert es wie ein Repository-Paket

TipTipp: Die richtige URL auf GitHub

Die URL muss direkt auf die .zip-Datei zeigen, nicht auf die Projektseite. Auf GitHub findest du sie unter Releases – Rechtsklick auf das Asset und Link-Adresse kopieren. URLs, die auf /releases/download/... enden, sind korrekt.

Methode B: Ein eigenes Repository hinzufügen

Hast du regelmäßig Pakete aus derselben Quelle (z. B. dem Schulserver oder einer Firma), lohnt sich ein eigenes Repository:

  1. Klicke im PCM auf das Zahnrad-Symbol
  2. Füge unter Repositories die URL der Repository-Indexdatei (JSON) hinzu
  3. Die Pakete der Quelle erscheinen anschließend im Reiter Browse und lassen sich ganz normal installieren und aktualisieren

Fallback: Installation aus einer Datei

Funktioniert keine der URLs (z. B. offline oder hinter einer Firewall), lade die .zip-Datei manuell herunter und nutze im PCM die Schaltfläche Install from File. Das Ergebnis ist identisch.

WarningSicherheitshinweis

Plugins sind Programme – sie werden auf deinem Rechner ausgeführt und haben dieselben Rechte wie du. Installiere deshalb nur Pakete aus Quellen, denen du vertraust. Bei GitHub-Projekten: wirf vor der Installation einen Blick in den Quellcode und prüfe, wann zuletzt ein Update erschienen ist.

Schritt 4: Pakete verwalten

Aktualisieren

  1. Wechsle zum Reiter Updates
  2. Aktualisiere einzelne Pakete per Klick oder alle auf einmal mit Update All

Deinstallieren

  1. Wechsle zum Reiter Installed
  2. Klicke beim betreffenden Paket auf Uninstall
  3. Starte KiCad neu – der Menüeintrag bzw. Toolbar-Button verschwindet, die restlichen Konfigurationen deines Projekts bleiben unberührt
TipTipp: Versionen festhalten

In der Detailansicht eines installierten Pakets siehst du die exakte Version. Notiere sie dir für die Dokumentation (z. B. in der Schule oder im Team) – so wisst ihr später, mit welchem Stand ein Projekt gebaut wurde.

Theorieteil: Wie der PCM funktioniert

Ein PCM-Paket ist im Kern eine .zip-Datei mit einer metadata.json. Darin stehen Name, Version, Beschreibung, Homepage und – wichtig – die kompatible KiCad-Version. Der PCM vergleicht diese Angabe mit deiner installierten Version und warnt bei Inkompabilität.

Das Repository selbst ist nur eine große Index-Datei (JSON), die alle verfügbaren Pakete samt Download-URLs listet. Genau deshalb funktioniert Methode B aus Schritt 3: Jede URL, die so eine Index-Datei ausliefert, kann als Repository eingetragen werden – der offizielle Server ist nur der Standardfall.

Plugins im engeren Sinne sind Python-Action-Plugins: Skripte, die beim Start von KiCad geladen werden und eigene Menüeinträge, Buttons und Dialoge registrieren. Ihre Dateien liegen nach der Installation unter 3rdparty/plugins/<paketname> – dort kannst du auch nachsehen, was ein Plugin konkret tut.

Tipps und Tricks

TipEigenes Plugin testen

Du willst selbst ein Plugin schreiben? Verpacke deinen Code mit einer metadata.json in eine .zip-Datei und installiere sie über Install from File. Genau so werden Plugins später auch von anderen installiert – ein guter Rundum-Test vor der Veröffentlichung.

TipOffline weitergeben

Kein Internet im Klassenraum? Lade die Paket-.zip-Dateien zu Hause herunter und gib sie auf einem USB-Stick weiter – Install from File funktioniert komplett offline.

WarningHäufige Fehler
  • Plugin erscheint nicht: Starte KiCad neu – Plugins werden nur beim Programmstart geladen.
  • Inkompatible Version: Ein Paket für KiCad 9 muss nicht in KiCad 10 funktionieren. Achte auf die Versionsangabe in den Paketdetails.
  • Repository nicht erreichbar: Hinter einer Firewall oder mit Proxy kann der PCM das Repository nicht laden. Nutze in dem Fall Install from File mit einer manuell heruntergeladenen .zip.

Nächste Schritte

Jetzt, wo du Plugins installieren kannst, kannst du:

  • Im offiziellen Repository nach Bibliotheken für deine Bauteile stöbern
  • Mit Python dein eigenes Action-Plugin schreiben
  • Pakete ausprobieren, die dir den Workflow erleichtern – von BOM-Export bis DFM-Prüfung

Viel Erfolg beim Erweitern von KiCad!
